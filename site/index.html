Install, step by step

Didn't work? Do it like this.

Claude Code

  1. Open a terminal and run:
    claude plugin install crux --marketplace fontai/crux
  2. Error unknown option '--marketplace'? Your Claude Code is older. Run these two lines instead, or update Claude Code:
    claude plugin marketplace add fontai/crux claude plugin install crux@fontai
  3. Start a new Claude Code session. Already running sessions won't see CRUX.
  4. Try it: crux path/to/document.pdf. The first run may ask whether CRUX may run. Choose Yes, and don't ask again.
  5. Check that it's installed: claude plugin list must show crux@fontai.

Claude app desktop · web

A. As a plugin (recommended, easy updates)

  1. In Claude, open Settings → Customize and switch to the Plugins tab.
  2. Click + Add → Add marketplace → Add from a repository.
  3. Paste fontai/crux and click Sync. If a notice offers Grant access, you can close it. It only turns on automatic updates.
  4. Find Crux in the list, click Add, then Continue.
  5. Click Try in chat, or open a new chat, attach a document and write /crux.
  6. To update later: open Crux in Plugins and click Update.

B. As a skill (if you don't see Plugins)

  1. Download crux.zip. Don't unzip it.
  2. Settings → Customize → Skills → + Add → Upload skill and choose crux.zip.

Both: Settings → Capabilities → Create and edit files must be on (“Skills need this on”), and it needs Artifacts on too. For fact-checking, the chat needs web search; without it CRUX offers the Quick depth.

Claude Team or Enterprise? Code execution is turned on by an owner in Organization settings → Plugins & skills. An owner can also upload CRUX once and share it with the whole organization.
Names in Claude changed? Anthropic's guide to skills always has the current steps.

Already installed? Update

CRUX tells you when a new version is out. To update:

  • Claude app, installed as a plugin: Settings → Customize → Plugins → Yours → Crux → Update. Then start a new chat.
  • Claude app, installed from crux.zip: download the new crux.zip, then in Settings → Customize → Skills → Yours remove the old CRUX and upload the new zip via + Add → Upload skill.
  • Claude Code: run the line below, then start a new session.
    claude plugin marketplace update fontai && claude plugin update crux@fontai

Still stuck? Tell us, or ask Claude: “Read https://github.com/fontai/crux/blob/main/README.md and install the crux skill.”

What you get

One screen instead of forty pages.

Built for people who get long, often AI-written analyses and have to make a decision based on them.

01

Verdict first

Approve, Revise, Return or Missing info, with one sentence why. Many readers stop here.

02

The summary

Main message, key points, risks and gaps, and questions worth asking the author. Each point links to its page or section.

03

A quality score

Seven criteria on a 1–5 scale, each backed by evidence. Key claims are checked on the web, and cited sources are checked to see whether they exist.

04

The brief behind it

What was the author probably asked to do, and why? It helps when you don't know where the document came from.

How it works

Say “crux” and hand it the document.

Markdown, Word, PDF or pasted text. CRUX replies in your language, whatever the document's language.

1

Give it the document

crux report.pdf, or attach the file and write “crux”.

2

Answer four questions

What to do, how deep, the author's brief (if you have it), and what you need to decide.

3

It reads and checks

In Claude Code, separate helpers do the research and return only short findings, so your session stays light.

4

You decide

A short answer first, about 20 lines. Say “full” for every detail, or ask to save or export it.

How deep

You always know how long it takes.

Pick the depth before it starts. Long documents (50+ pages) take about half as long again.

Quick~1–3 min

Only the document itself: consistency, gaps, typical AI defects. No web.

Standard~5–10 min · recommended

Plus a web check of the claims the conclusions rest on, and of the sources it cites.

Deep~15–30 min

Plus independent research by parallel helpers, and every source checked.

Example answer

What it looks like.

A fictional 40-page analysis, the one from the video: should a 120-person company move to a four-day week? CRUX's real answer at Quick depth. Short by default; ask for the full version if you need it.

🟡 Revise (no fact check) — the pilot is cheap, but the case behind it is shaky

Brief: inferred (“should we move to a 4-day week, and how?”) · Your decision: approve a 3-month pilot

Main message: Move all 120 staff to 100% pay for 80% of the hours, with days off staggered across teams. Test it with a pilot first. §15.2

  • Of the five models compared, they pick Option C, staggered teams, to keep Friday and Saturday customer coverage. §7.8–7.9
  • They propose a 6-month pilot (Feb–Jul 2027, 56 people), not 3 months. Drivers and sales are left out as a comparison group. §10.3
  • Cost: EUR 240k one-off, plus EUR 286k a year including 6 new hires. §8.2–8.3
Recommendation
  • Approve only the pilot and its budget. Do not approve point 1 (the 4-day week for all employees) or the hires. §15.2
  • First ask for success criteria that match the business case. Three months can't show effects on turnover or peak season. §10.4
Risks
  • 🔴 The whole case rests on a single source: the “Henley Institute” study of a 27% productivity gain. Other claims have no source at all. §5.4 §6.2–6.3
  • 🔴 The headline net saving of “EUR 1.2 million” a year doesn't match the document's own financial model, which gives EUR 412,000. s. 3 §15.1 vs §8.5
  • 🔴 The pilot's pass bar is +15% productivity and ≥ 95% output. The business case needs +25% just to keep output flat. §10.4 §14.2
Questions for the author
  1. Which figures are right: EUR 412k or 1.2M, and 46 or 64 warehouse staff? §4.2 vs §7.9
  2. What happens if productivity rises 10% instead of 27%? The sensitivity analysis never changes that number. §8.7

Score 2.6/5 · 🔴 Evidence 2 · 🟡 Specificity 3 · 🔴 Consistency 2 · 🟡 Decision use 3 · 🟡 Depth 3 · ⚪ Alignment 4 (indicative) · ⚪ Accuracy not checked

Full version: 6 more risks (an empty Risks section, the pilot skipping drivers and peak season, how overtime falls by 50%), the reasoning behind each score, and an estimate of the author's effort. Write “full”.

What CRUX promises

Strict, and never makes things up.

No made-up sources

It cites only pages it actually opened. Everything else is marked unverified.

Strict scoring

AI tends to go easy on AI-written text. CRUX needs the same evidence for praise as for criticism.

Your data stays yours

Web searches use generic terms about the topic, never names or numbers from your document.

Always up to date

It checks once a day and tells you when a new version is out.
